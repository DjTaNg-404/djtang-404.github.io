# 数学系转大模型最终总结

不知不觉已经一年过去了。去年 2025 年 7 月 7 日在小红书发了“数学系转算法 ｜ 大模型学习记录 Intro”，今年 2026 年的 7 月则是毕业作为校招生正式入职公司了。刚上了一周班，趁周末总结一下这一年的经历，同时也说一些我在实习、秋招春招的一些 tips 吧。

## 关于大模型

学习过程的很多笔记都发在小红书上了，从我的笔记可以观察出一个变化：我的标题从“数学系转算法”变到“数转码”再到“数学系转大模型”。为何会出现这种变化呢？

一是发现大模型的内容其实很广泛。前有 CNN、RNN、LSTM 再到 Transformer 的发展史；细致的也有各种 NLP 任务和对应的模型、算法；除了最基础的大模型架构和 SFT 微调，还有各种厂商自家的模型的架构以及独特的训练方法；同时大模型应用技术也层出不穷；不仅如此，在学术界也陆陆续续有人提出新的算法。虽然我们讨论的是“大模型”三个字，但是实际上包含的方向很多很多，需要学习的内容很多很多。

二是确定了自己的求职方向。以前可能只想着说“我要找大模型相关的工作”，但是具体进入了之后，会发现自己其实就只能找两个方向的工作：“大模型应用开发工程师”（也就是现说的 Agent 开发）和“大模型业务算法工程师”（算法岗）。前者会更偏开发，做的工作会更偏向于把业务流程用各种技术或模块如 RAG、Memory、写 Skills、设计 Agent 架构等具体落地；后者则是根据具体业务清洗训练数据并对大模型进行后训练微调或蒸馏，并将新的模型运用到具体的业务之中。像技术研究类、设计模型预训练和核心架构的岗位，根据自我认识是觉得去不了。

因此，在明确了这几点后，我就意识到自己不能只学习算法相关的知识，还需要把工程落地能力进行补齐。从我的笔记可以看出，不仅包含一些基础的算法内容，也包括例如 FastAPI、HTTP 这类可能更偏后端基础的内容、RAG 等技术的实现，还有一些和微调、LoRA、RL相关的记录。因此标题才会从“算法”变到“码”最后到“大模型”。

在还没入行的时候，可能只会喊几句口号式的“我要做大模型”；真正学进去，才发现里面的细节有多具体，也才看清自己更合适往哪条路走。

## 关于实习

对于实习而言，最难的问题是“如何找实习”。实际上找实习真的是需要很“机缘巧合”，特别是对于日常实习而言。一是必须得公司的某个组里确实缺人干活，并且有有招人名额（HC）来招实习生；二是你有机会看到这一条招聘消息并且投递；三是你的简历能被 HR 或者业务方看到。这几步真的是很看运气。只有过了这几步，走到邀请面试的阶段，才是真正靠自己实力的时候了。

所以总结下来，找实习的方法主要为这几条：

1. 找熟悉的朋友、同学、师兄师姐内推，同时帮忙跟进进度。
2. 加入各个企业的校园大使组建的企业招生群，关注校园大使转发的招聘信息和招聘活动。
3. 进入一些博主（可以是某个岗位的细分方向的博主）的社群，获取一手信息、寻求指导和交流。
4. 关注小红书等社交媒体平台，看是否有人转发招聘信息，或者是实习找继任的笔记，并直接联系。
5. 寻找一些有人实时整理的求职岗位文档，时刻关注是否有适合自己的公司或岗位。
6. BOSS直聘根据关键字检索与自己技术栈相关的岗位，并积极沟通。
7. 进入对应公司的招聘官网进行投递。

这几个方法，也是我按照重要性、可靠性从高到低排列了。其实前期我们的目的只有一个，即是让自己的简历能被看见。熟人内推并不是给个内推码就完事，而是帮忙推到业务部门，同时能够得到对应的反馈，这才是最重要的。校园大使推荐、小红书等社交媒体上说发邮件等方式也和熟人内推同理，目的就是为了简历被看见。一些博主经营社群久了，一是社群里本身就有很多大佬，二是也有不少人通过社群的帮助找到工作且也会分享一些求职咨询。同时社群也是个能打破信息差的途径。

“简历被看见”只是第一步，正所谓打铁还需自身硬，因此是否能真正找到实习，最重要的是自己简历写得如何、面试表现如何。

## 关于秋招春招

秋招春招和找实习同理，第一步也是要让简历能被 HR 和业务方看见。那么在这里我分享一下和做项目、秋招春招相关的事情吧。

根据我自己的经历，总结下来的是这三条经验：

1. 做项目要带自己的思考，要么落地自己的idea，要么在别人的项目上吃透思路、加上自己的改动。
2. 把项目开源，并主动和他人交流，靠外部视角发现提升空间。
3. 搭个人博客，把过程沉淀成可展示的输出。

回顾我的简历上写过的项目经历：一个是机器学习可视化学习平台智能助手（构建面向机器学习学习与实验场景的可视化学习平台与智能问答助手）；另一个是阿城 ChatTutor —— AI 学习陪伴桌宠（基于 LangGraph 多智能体架构的苏格拉底式 AI 学习助手，支持 Web 与桌面宠物双端体验）。

详细说说第一个项目吧，这个项目其实是在学习完 RAG 之后做的。当时就在思考，如果只是去 GitHub 上拉取别人的“企业级” RAG 助手并且跑通，这么做真的有意义吗？后面就觉得，不如在自己身边去找具体的实现场景。

恰逢以前打数学建模比赛时把大部分的机器学习算法都略微接触过，且在港城大（东莞）的课程里更进一步的学习了对应的理论知识。在学习的时候其实觉得空白的公式是很枯燥的，如果有对应的可视化可能会更加清晰，让人更容易理解。例如学习 SVM，只是数学公式描述或文字描述，远远比不上一张平面图加上一条横线（超平面）来得清晰。此外，像 Datawhale 也有很多开源的学习资料。于是想到：能不能做一个可视化平台，同时嵌入了大模型问答系统，大模型问答的时候会检索开源的学习资料辅助回答，保证回答的准确性，因此才想到了做这个项目。

也正因为这个 idea 是我自己想的，具体落地的工作也是自己一步一步摸索的，因此在面试中就能够很清晰、顺畅的把项目背景、实现过程、出现过的问题都表达得很清楚。对我而言，做项目最好是落地自己的 idea，自己做的东西在面试时去讲述会更有自信、更有底气。

至于为什么要把项目开源？一个原因是将项目开源后，能够在简历上附上 GitHub 链接，有的面试官会把项目代码拉取下来看的（我的老铁厂一面面试官，后来的 mentor ，当时确实是拉取了我的代码下来看）。

此外，开源代码后可以分享给一些志同道合的朋友。之前我的 Desktop-Claw 项目本来只做了 Mac 版本，并不适配 Windows 系统。有个同学拉取了我的代码并测试了 Windows 系统可跑，提了个 issue 后我也将项目修成两个系统都支持了。

阿城 ChatTutor 这个项目本身就是诞生于 AI Hackathon Tour，由 ModelScope 和 Datawhale 联合举办的黑客松比赛。当时项目也入围了清华大学深圳国际研究生院站全国复赛，在复赛现场得到了资深导师们的指点，同时也有很多观众体验过我们的项目。同时在港城大（东莞）的校园开放日中也有专门的展台展示了我们这个项目，也有很多高中生参与体验了项目。

有这些交流的经历，不仅能够知道如何才能完成一个真正的“产品”，同时也能知道当下人们的痛点还有什么、人们更期待出现什么产品来帮助自身。这些信息都是在交流中获得的，如果只是在工作室里埋头苦干开发产品是完全得不到的。在和别人交流的过程中，你也能知道自己能不能把项目讲清楚，这也有助于自己在面试中更好地向面试官描述自己的项目。

关于是否需要做个人博客，这就看个人需求了。我从本科开始就一直想做个博客，之前只做了一个很简陋的初版，用于存档自己打 ACM 时留下的各种算法、数据结构模板，还有学习 MATLAB 和数学建模时的笔记。最近也重新设计了一个博客，把自己的文章都迁移了上去。而且拥有一个个人博客，也是让人快速认识你、了解你的一种方式。毕竟一份简历最多两页，篇幅始终有限；对你感兴趣的人，会顺着博客地址去浏览，从而更充分地了解你。

## 总结

一年前还在小红书上写《数学系转算法》，如今已经以校招生的身份入职了。这一年很长，经历了许多事，学了不少东西，也得到很多人的帮助。回过头看，这一年找工作的经验归结起来就一句话：**方向要想清，简历要被看见，实力要坐实，剩下的交给时间。**希望我的经验能帮到更多人。
