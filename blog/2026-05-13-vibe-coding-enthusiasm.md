# 逐渐对 vibe coding 失去热情

其实觉得自己确实并没有很跟进时代的步伐。之前小龙虾热的时候没有跟着体验，现在似乎热度没这么火了才开始玩 QClaw，能连接微信真的很方便。

此外，自己最近也在对自己的需求进行 vibe coding，期待做出些 AI 项目出来。但最后却发现，自己做的可能还是伪需求，只是自己一时兴起才做，做出来也没有真正解决自己什么需求。

例如最近做的项目：从音频、文本、当场录音转录的文本中自动生成 PPT，并制作可直接用于发布的视频。

乍一听，觉得这个确实很值得做，但是实际做下来确实引出了很多问题。

1. 如果可以用 Skills 来完成的事情，那么你做这个东西还有意义吗？

   虽然我知道有些时候 Skills 有 Skills 的受众，客户端产品有客户端产品的受众。但是当你意识到一个 Skill 也能完成的时候，你会去思考自己做的是不是真的是无用功。

2. Vibe coding 真的能对代码负责吗？

   因为这次做这个项目，完完全全我都没有看代码。因此当出现 bug 的时候，我完全不知道怎么改，因为我不知道它这个框架具体是怎么用的。我只能从用户使用感受上、功能的实现上去挑问题，但我完全不知道如何在框架的层面上去分析、去发现问题。

   因此我会感觉我对代码是缺少了一种掌控感，没有完全对代码负责。

3. 自己单打独斗真的比得过大公司和明星开发者吗？

   首先最大的感触是 Claude Code 和 Codex 都陆续推出桌宠，下场做桌宠后可谓是一脚把我给踢死了。虽然说我做的桌宠也都是为了学习，一个是为了学习 LangGraph，另一个是为了学习 OpenClaw。

   其次是最近也有一篇爆火的文章，说让 AI 倾向于输出 HTML，而非 Markdown。随后我身边就有人测试了一下，用 HTML 写 PPT 的效果确实不错，同时还能支持 LaTeX 数学公式。这一下又把我做的那个项目给踢飞了。

在这些信息的冲击下，可以说我感觉最近过得确实是浑浑噩噩，似乎都一直在做无用功。

我觉得以后还是减少 vibe coding 的频率了。虽不是恢复古法编程，但我认为在使用 AI 来 coding 的前提必须是你本身也懂 coding。

我总感觉，宣传说 AI 可以代替程序员的，要么就是 0 代码基础的人；要么就是代码实力本身就很强悍、懂得如何发挥 AI coding 实力的人。我觉得我们作为中间层，并且作为一个即将就业的校招生，应该要往后者学习。

想起来了之前的一个议题：“以后肯定会是 vibe coding 的天下，例如现在有多少人还关注并学习汇编语言。”但我觉得，人们不关注汇编语言，而是直接操作高级语言，更大的原因是其实基于“规则”的。

反而 vibe coding 是基于“黑盒”的、基于概率的。我认为 vibe coding 和古法 coding 并不会演变成高级语言和汇编语言的状态。

同时呢，我也希望自己能够再找到一些学习的乐趣吧。

回想自己最后获得感的时候，是不断学习大模型算法并总结成笔记的时候；是先看 LangGraph 文档写出 demo 后，再让 AI 润色成开源项目级别，并以此学习工程化代码及结构的时候；是学习 OpenClaw 的构造方法及特点后，自己浮现了一个轻量款的 Agent 的时候。

希望自己能进一步找回那份激情和好奇心，并沉下心来学习吧。
